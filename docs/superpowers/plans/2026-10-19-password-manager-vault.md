# Password Manager Vault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the prototype password manager with an encrypted, persistent vault, searchable website list, ten-minute reveal session, copy actions, and external website links.

**Architecture:** Add a Qt storage wrapper that atomically saves an encrypted vault payload plus a plaintext website URL index. Rebuild the tab around setup, add, and browse states while using the existing Argon2id and AES-256-GCM core functions.

**Tech Stack:** C++17, Qt 6 Widgets/Core, QSaveFile, QDataStream, existing Argon2id/AES-256-GCM vault functions.

**Spec:** [2026-10-19-auth-password-manager-android-design.md](../specs/2026-10-19-auth-password-manager-android-design.md)

## Global Constraints

- “If no vault exists, show only the master-password setup view.”
- “A credential consists of the website URL, username, and user-entered password. Do not generate or substitute a password.”
- “Store a separate plaintext website URL index so websites can be listed and searched while locked.”
- “The ten-minute reveal window is absolute from the first successful master password entry for viewing; activity does not extend it.”
- “Website URLs are intentionally visible in the local app data file to support this behavior.”
- Do not modify QR Sync source or behavior.
- Do not add or run automated tests unless requested; compile the affected application targets for verification.
- Do not commit or push.

## Review Focus

- Missing or corrupt vault file shows setup or a recoverable error without replacing valid data.
- Wrong master password or tampered ciphertext exposes no partial username/password data.
- Website index and encrypted entry list are updated in one atomic file replacement.
- Expiry clears revealed UI values and forces master-password entry for the next reveal.
- URL normalization accepts only valid HTTP/HTTPS destinations and rejects other schemes.

### Task 1: Add atomic vault file storage

**Files:**
- Create: `ui/PasswordVaultFileStore.h`
- Create: `ui/PasswordVaultFileStore.cpp`
- Modify: `CMakeLists.txt`

**Interfaces:**
- Consumes: `auth::Argon2Params`, `auth::VaultEntry` encryption metadata and ciphertext generated by `auth::EncryptVault()`.
- Produces:

```cpp
struct PasswordVaultFile {
  std::vector<uint8_t> salt;
  auth::Argon2Params params;
  std::vector<uint8_t> ciphertext;
  QStringList websites;
};

class PasswordVaultFileStore {
 public:
  explicit PasswordVaultFileStore(QString filePath);
  bool exists() const;
  PasswordVaultFile load() const;
  void save(const PasswordVaultFile& vault) const;
};
```

- [x] **Step 1: Define the stored-vault interface**

  Add the struct and class declarations to `ui/PasswordVaultFileStore.h`. Store the path as a private `QString` member.

- [x] **Step 2: Implement versioned load and atomic save**

  In `ui/PasswordVaultFileStore.cpp`, use `QDataStream` with a fixed magic value and format version, then serialize KDF parameters, salt, plaintext website index, and ciphertext. Use `QSaveFile` for replacement and check stream status, lengths, version, and write/commit results. Never serialize `VaultEntry` plaintext to disk.

- [x] **Step 3: Add the storage source to AuthQt**

  Add `ui/PasswordVaultFileStore.cpp` and `.h` to the `AuthQt` source list in `CMakeLists.txt` for desktop and Android configurations.

- [x] **Step 4: Compile AuthQt**

  Run: `cmake --build build --target AuthQt`

  Expected: storage wrapper compiles and links.

### Task 2: Implement setup and credential-add states

**Files:**
- Modify: `ui/PasswordManagerTab.h`
- Modify: `ui/PasswordManagerTab.cpp`

**Interfaces:**
- Consumes: `PasswordVaultFileStore`, `auth::GenerateSalt()`, `auth::DeriveKey()`, and `auth::EncryptVault()`.
- Produces: setup state for a missing vault and an add state with website, username, and entered password fields.

- [x] **Step 1: Replace prototype member state and slots**

  Remove random credential generation, the old Retrieve slot, and the current in-memory-only `vault_exists_` flow. Add `QStackedWidget` pages for setup, add, and browsing; retain only the encrypted file metadata, active derived key, and currently revealed entries needed by the UI.

- [x] **Step 2: Initialize the app-local vault location**

  Construct `PasswordVaultFileStore` with `QStandardPaths::writableLocation(QStandardPaths::AppDataLocation) + "/password-vault.dat"`; create the parent directory. If the file does not exist, show only setup. If it exists, load the plaintext URL index and show the locked browse state.

- [x] **Step 3: Set up the master password and empty vault**

  Derive a key using `auth::kDefaultArgon2Params`, generate the salt, encrypt an empty entry list, and atomically save the vault file. On success, clear setup inputs and show the add workflow. On failure, retain setup and display the error.

- [x] **Step 4: Save user-entered credentials**

  Add a password input with password echo mode. Require non-empty website, username, and password; normalize the URL using the rules in Task 3. If no active derived key is available, prompt for the master password and decrypt the existing vault before appending. Encrypt the full list, update the URL index, and save atomically. Clear credential inputs and wipe temporary plaintext after successful save.

- [x] **Step 5: Compile AuthQt**

  Run: `cmake --build build --target AuthQt`

  Expected: setup and add state implementation compiles and links.

### Task 3: Implement search, reveal session, copy, and open-link actions

**Files:**
- Modify: `ui/PasswordManagerTab.h`
- Modify: `ui/PasswordManagerTab.cpp`

**Interfaces:**
- Consumes: `PasswordVaultFileStore::load()`, `auth::DeriveKey()`, and `auth::DecryptVault()`.
- Produces: searchable website rows, a fixed ten-minute reveal session, per-field clipboard actions, and validated external URL opening.

- [x] **Step 1: Build the locked website list and search field**

  Add a search field and list widget populated from `PasswordVaultFile::websites`. Filter case-insensitively by website. Keep this list visible while locked; do not display usernames or passwords from the plaintext index.

- [x] **Step 2: Require master password before the first reveal**

  When a website is selected for viewing, prompt for the master password if no reveal session is active. Derive the key from stored KDF metadata and call `auth::DecryptVault()`. On success, retain decrypted entries for the session and start `QElapsedTimer`; on failure, show an error and keep all secrets hidden.

- [x] **Step 3: Enforce the absolute ten-minute session**

  Add a `QTimer` that checks elapsed monotonic time. At ten minutes, clear revealed username/password widgets and wipe decrypted password buffers, stop the active reveal state, and require another master-password prompt before the next reveal. Do not extend the session on user activity.

- [x] **Step 4: Add copy and website-link actions**

  For a revealed entry, add separate username and password copy buttons using `QGuiApplication::clipboard()`. Add a website action using `QDesktopServices::openUrl()`. Prepend `https://` when no scheme is present; open only valid URLs with `http` or `https` schemes.

- [x] **Step 5: Compile AuthQt**

  Run: `cmake --build build --target AuthQt`

  Expected: all password manager UI and storage code compiles and links.
